**Crafting System – Definition**
*(Updated 2026-09-02. Authority for how crafting works. Minigame catalog in §11. Fidelity + A2 build order in §16.)*

ProjectVision.txt keeps the short system blurb and a link here. Item durability, hold/place, and factory rules stay in ItemSystemImplementation.txt. Station actors and sockets stay in the Structure system; this file only states what crafting needs from a station.

Content assets use `DA_Type_Name` (`DA_Recipe_SharpenedStone`, `DA_Minigame_Grind`, `DA_Item_Stone`, `DA_Structure_Workbench`).

Open sections are marked OPEN. Leave those until they are closed here.

Fidelity (read §16 before treating §11 as an A2 checklist):

- **Vision** — presentation stages / morphs, authored events (flip, crack), resume on selected long crafts as Items. Destination.
- **Shippable** — looks like the craft (presentation SKM morph and/or growing bones). Flip: later.
- **Core Loop / A2 MVP** — session + prompt + Factory consume/spawn. Grind motion on two live stones. Twist presentation. R / player damage returns the bound items.


### 1. Goals

- Crafting is how gathered items become tools, parts, materials, and later food-prep / metalwork products.
- Interaction stays manual: hold the right items, optionally park one on a station slot, get a quiet prompt, press the default action button, play a minigame.
- Every craft is a minigame, including simple ones. Types, movement modules, and meters are in §11.
- At most three item *types* in one recipe (two hands + one station slot). Longer chains are staged recipes (output of A is an input of B).
- Tools used in a craft are held. They are consumed only when the recipe says so.
- Minimal UI. One prompt, wheel to cycle matches, then a progress / minigame band in the same bottom-middle area.


### 2. Constraints

- A slot matches an exact item data asset or a gameplay tag on `UItemDefinition::ItemTags`.
- A hand that holds a stack (`count ≥ 2`) is not a legal craft socket. Unstack first (existing R + mouse rule).
- Hands craft is the absence of a station. The snapshot has no station in context.
- The recipe freezes when the session starts.
- A crafted hatchet is a new item definition (dual-mesh). Part-break stays on the Item durability design until that ships.


### 3. Context snapshot

Crafting reads a snapshot rebuilt when something relevant changes: hand attach / detach, Neutral vs Extended, look-at station, station slot contents.

Snapshot sockets:

- Left hand Instance (or Unarmed)
- Right hand Instance (or Unarmed)
- Station-in-context: the structure the player is looking at, or the structure that already holds the slotted item, plus that slot’s Instance (may be empty)

A snapshot does not match while:

- Either hand holds a stack
- Either hand is Extended — prompt and match list hide while any occupied hand is Extended
- A hand the recipe does not bind is occupied by a real item (that hand must be Unarmed; see §5.8)

Hands / ground craft: recipe `Station` unset, snapshot station empty.

Station craft: snapshot station identity equals the recipe’s station asset.


### 4. Pieces

Enums live in `WoodcraftTypes.h`:

- `ECraftingSlotRole` — Ingredient, Tool, Workpiece
- `ECraftingSlotMatchMode` — ExactDefinition, RequiredTag, Sharpenable
- `ECraftingAppearanceMode` — LiveMeshes, Morph, SkeletalPhase
- `ECraftingMorphSampleMode` — Lerp, HoldAndPop

Structs live next to the type that owns them (`FCraftingSlot` / `FCraftingOutput` / snapshot / match on the recipe header because `FindMatches` lives there; session on the component header). Movement numbers live on the movement classes.

**`UCraftingRecipeDefinition`** (Primary Data Asset)
One asset per craft (`DA_Recipe_SharpenedStone`, `DA_Recipe_Cordage`, `DA_Recipe_StoneHatchet`, …).
`GetPrimaryAssetId` type: `CraftingRecipe`.

- `DisplayName` — used in the prompt
- `Icon` — selector / guidebook later
- `Station` — optional soft pointer to one station-identity asset (`UStructureDefinition` when Structures exist; `UPrimaryDataAsset` until then). Unset = hands craft. Set = that station only. Hands recipes stay hands-only.
- `Slots` — array of `FCraftingSlot` (usually 2, at most 3)
- `Outputs` — array of `FCraftingOutput` (one or more)
- `Minigame` — one `UCraftingMinigameDefinition` asset. Minigame fields stay on that asset.

**`FCraftingSlot`**

- `Role`: `Ingredient`, `Tool`, or `Workpiece`. A2 recipes use Ingredient.
- `Match`: exactly one of
  - `ExactDefinition` — this item data asset
  - `RequiredTag` — any item whose `ItemTags` contains the tag (`Item.Tool.Knife`, `Item.Fiber`, …)
  - `Sharpenable` — Hone only. Runtime: `UDurabilityItemFragment::bCanBeSharpened` and `CurrentHeadHealth < MaxHeadHealth`
- `bMustBeHeld`: `true` = must bind to a hand (tools). `false` = hand or the single station slot
- `bConsumed`: Factory-destroy that Instance on success
- `DurabilityCost`: `0` = none. On success, applied to the bound item if it has durability. Typical tools: kept, cost > 0 once wear ships

One instance per slot.

**`FCraftingOutput`**

- `ItemDefinition`
- `bAutoEquip`

A single-output recipe sets `bAutoEquip` true. Multi-output recipes flag at most one output. If `bAutoEquip` is false, that output piles.

**`UCraftingMinigameDefinition`** (Primary Data Asset)
Appearance, camera, presentation, and one instanced `UCraftMovement`. See §11.3 / §11.9.
`GetPrimaryAssetId` type: `CraftingMinigame`.

```cpp
UPROPERTY(EditDefaultsOnly, Instanced, Category = "Minigame")
TObjectPtr<UCraftMovement> Move;
```

`FindMove<T>()` on this asset matches `UItemDefinition::FindFragment<T>()`.

**`UCraftMovement`** (abstract, `EditInlineNew`, `DefaultToInstanced`)
Data only. Same rules as item fragments: numbers and restrictions, no Tick.
Folder: `Public/Crafting/Movements/` (mirrors `Public/Items/Fragments/`).

- Interpreter uses `FindMove<T>()` and runs that class.

Concrete A2 classes:

- `UGrindActiveCraftMovement` — always in contact. Stroke `D`, travel volume, min speed (gate) / max speed (cap), planted vs working strengths.
- `UCircleAlternateCraftMovement` — animation / mouse slices. Slice radians, gesture radius.

Later classes (same naming, add when that craft ships): `UGrindPassiveCraftMovement`, `UGrabPullCraftMovement`, `UCircleContinuousCraftMovement`, `UStrikeCraftMovement`.

The interpreter on `UCraftingComponent` uses `FindMove<T>()` the same way items use `FindFragment<T>()`, then runs that move. Movement objects do not run the session.

**`UCraftingComponent`** (on the player)
Owns:

- `RecipeAssets` — `TArray<TSoftObjectPtr<UCraftingRecipeDefinition>>` (A2 / MVP table)
- Snapshot rebuild and selected match index
- The live session
- The interpreter tick (one class, every minigame type)
- Start / cancel / commit
- Session presentation actor pointer

Matching: `UCraftingRecipeDefinition::FindMatches(const FCraftingSnapshot&, const TArray<UCraftingRecipeDefinition*>&)` returns `TArray<FCraftingMatch>` (recipe + slot bindings).

**`FCraftingSession`** (struct at the top of `CraftingComponent.h`)
Created on E, cleared on success, R, fail, or inbound player damage. Holds:

- Frozen recipe
- Frozen bindings (Item Instances / actors at start)
- Progress `0–1`
- Minigame phase
- Engage state
- Live presentation pointer (session-only)

The session is a struct on the component.

A2 / MVP file layout:

- `Public/Crafting/CraftingRecipeDefinition.h` + `Private/Crafting/CraftingRecipeDefinition.cpp`
- `Public/Crafting/CraftingMinigameDefinition.h` + `Private/Crafting/CraftingMinigameDefinition.cpp`
- `Public/Crafting/Movements/CraftMovement.h`
- `Public/Crafting/Movements/GrindActiveCraftMovement.h` + matching `.cpp` if needed
- `Public/Crafting/Movements/CircleAlternateCraftMovement.h` + matching `.cpp` if needed
- `Public/Player/CraftingComponent.h` + `Private/Player/CraftingComponent.cpp` (player-only, same folder as HeldItems)
- Crafting enums in `Public/Core/WoodcraftTypes.h`
- `AWoodcraftCharacter` creates the component as a default subobject
- Content: `DA_Recipe_*` next to the primary output item. `DA_Minigame_*` in `Content/WoodcraftSurvival/Crafting/Minigames/`.


### 5. Matching and binding

For each recipe, assign every slot to a snapshot socket.

1. `bMustBeHeld` slots consume hands first. Fail if not enough free hands.
2. Remaining slots fill leftover hands, then the station slot.
3. Each socket is used at most once.
4. A `Tool` slot is always `bMustBeHeld`.
5. Hands recipe: every slot lands on a hand. Station-in-context is empty.
6. Station recipe: station identity matches `Recipe.Station`. At least one slot has `bMustBeHeld == false` so the extra socket is usable.
7. Match test per slot: bound item’s definition == `ExactDefinition`, or item tags contain `RequiredTag`. Resume (later, selected recipes): a bound item with the in-progress marker for this recipe and `Progress < 1` also matches that slot.
8. A hand the recipe does not bind is Unarmed. Strip binds the stalk only; the Unarmed hand is the working hand.
9. A `Workpiece` role is the body that can become an in-progress item on a later resumable craft. At most one per recipe. Workpiece role: later resumable crafts.

Several recipes may match one snapshot. That is a list.

A2 two-hand working / planted split: Right = working / primary, Left = planted. Handedness settings can flip this later.


### 6. Prompt and selection

Shown only when both hands are Neutral and the match list length ≥ 1.

Bottom-middle, slightly transparent text, same band as stamina / future progress. Container-list language: selected row full; if `N > 1`, one neighbor above and below smaller and faded.

- `N = 1`: `[E] Craft {DisplayName}`
- `N > 1`: same line on the selected row; wheel moves selection and wraps
- Later resume: if a bound socket is an in-progress item for that recipe, the row reads `[E] Resume Crafting: {DisplayName}`

E is the default action button. The prompt shows the current key.

Mouse wheel while this prompt is up cycles matches. Same wheel as container UI; a hand Extended for container-take already hides this prompt.


### 7. Starting, cancelling, committing

**Start (E)**
Selected match freezes into a session. Crafting Input Mapping Context is added. Move off. Camera-look stops driving combat aim; mouse is minigame input. Q pickup / place off. LMB / RMB stop swinging. View blends to the minigame craft frame, then locks. Prompt hides. Progress / minigame UI uses the same bottom-middle band.

The recipe stays frozen for the life of the session.

**Cancel (R)**
Session cleared. IMC removed. Bindings stay in the hands (A2 and every recipe that is not marked resumable). Prompt may show again if the snapshot still matches.

Engage **release** pauses GrabPull and GrindPassive. The session stays up.

**Interrupt — any damage the player receives**
Same teardown as R. Immediate. Includes combat hits, fall damage, and any later damage channel that hurts the player.

`UCraftingComponent::NotifyOwnerDamaged()` is the hook. Player BP / future health code calls it.

Bound items stay in their sockets for the session. Q is off. Later multiplayer locks those sockets for other players until the session ends.

**Success**
Order:

1. Apply each slot’s `DurabilityCost` to the bound Instance
2. Factory-destroy every bound Instance with `bConsumed` (HeldItems detaches first, then `UItemFactorySubsystem` destroys actor + Instance; Unarmed fills the empty hand)
3. Spawn each output via ItemFactory
4. Auto-equip at most one output (see §8)
5. Remaining outputs pile at craft origin as separate world actors
6. Clear session, remove IMC

**Fail**
A minigame may own a fail meter `0–1`. When it fills: session ends, tools stay, `DurabilityCost` is skipped, fail outputs pile if the recipe lists them.


### 8. Outputs, auto-equip, piles

**Craft origin**

- Hands craft: player location, in front / at feet (same idea as a drop)
- Station craft: station slot / work surface

**Auto-equip hand**

1. If any bound slot has `Role = Tool`, use the other hand
2. Else use the primary hand (Right until handedness settings exist)
3. That hand must be free after consumes
4. If auto-equip cannot run, that output piles instead

HeldItems grows a `ReplaceHeldItem(EHand, AItemActor*)` path for auto-equip (no pickup montage). Factory grows `DestroyItemActorAndInstance(AItemActor*)` as the only destroy path.


### 9. Stations (what crafting needs)

A station is a Structure. Crafting needs:

- A station identity: one structure data asset. The recipe’s `Station` field and the structure’s identity are the same asset
- Zero or one item slot on the shared socket frame already locked for items (`+Z` up, `+X` forward, item `PlacementOffsetTransform`)
- Detection: looked-at station, or the station that already owns the slotted item

Q-place / retrieve is Item + Structure work. Typical station craft: park one ingredient with Q, stand Neutral with the other item(s) in hand, prompt appears, E.

A2 / MVP snapshots: empty station socket. Workbench and Tie ship in A3.

**Workbench (one-slot station, T1)**
Identity `DA_Structure_Workbench`. One actor from ghost to finished.

- Slot: marked flat patch on the top. Shared socket frame.
- Tie (`DA_Item_SharpenedStone` + `DA_Item_Stick` + `DA_Item_Cordage` → `DA_Item_StoneHatchet`) is the first bench recipe.
- Test level may spawn a finished bench (Roadmap A3). Player-built is A4.

Build graph lives in Notes/StructureSystem/StructureSystemDefinition.txt. BOM: 3 Logs, 2 Cordage, 5 Sticks.

**Grindstone (no-slot station, T3)**
First sharpenable tools are **T3 copper**. Identity `DA_Structure_Grindstone`.

- Snapshot: looking at the grindstone, one `Sharpenable` tool in a hand, other hand Unarmed, both Neutral. Prompt `[E] Sharpen {ToolName}`.
- Live mutate while Engage is held: `CurrentHeadHealth` rises at `R`, `MaxHeadHealth` falls at `r`. Release pauses writes; session stays up. R / damage ends the session and keeps writes already applied.
- `CurrentHeadHealth` reaches `MaxHeadHealth`: auto-release Engage, green flash, end session.


### 10. Staged crafts, unfinished items, progression

Three types is a hard cap per recipe. Longer chains are several recipes.

T1 / Core Loop chain:

- `DA_Item_Stone` + `DA_Item_Stone` (hands, Grind) → `DA_Item_SharpenedStone`
- `DA_Item_FibrousStalk` + Unarmed (hands, Strip) → `DA_Item_PlantFiber` (Wood Scraps / Kindling: fire system)
- `DA_Item_PlantFiber` + `DA_Item_PlantFiber` (hands, Twist) → `DA_Item_Cordage`
- `DA_Item_SharpenedStone` + `DA_Item_Stick` + `DA_Item_Cordage` (workbench, Tie) → `DA_Item_StoneHatchet`

The hatchet is a new definition (StickHandle primary mesh + stone head secondary).

**Staged recipes**
Success of recipe A can spawn `UnfinishedX`. Recipe B consumes `UnfinishedX` and yields `X`. Two recipes. Example later: green bowl → fire harden.

**Resume — selected long crafts only (later)**
Twist, Tie, Strip, and A2 Grind complete in one sitting. R returns the original items.

Form (clay), Hammer (knap / forge), and other long shaping crafts may persist as **Items**:

- Snapshot already matches that recipe, and one bound item carries the in-progress marker fragment for that recipe.
- One in-progress mesh per resumable craft, or the fragment adds a skeletal mesh component at spawn. Choose when that craft ships.
- A point-of-no-return may Factory-replace the raw item with the in-progress item and disable R.
- Progress lives on that Item Instance as its own fields when this ships.

In-progress marker fragment + instance progress fields: later, Form / Hammer.

**Guidebook / unknown recipes — OPEN**
Prompt policy can follow the guidebook setting. Matching itself does not depend on known-state. Default lean: Discover (`[E] Craft ???` until learned).


### 11. Minigames

One interpreter on `UCraftingComponent`. Each recipe points at one `UCraftingMinigameDefinition`. Types are data.

Audio and VFX are curated from meter events (engage, valid stroke / slice / pull / pop / finish, fail tick, authored events).

#### 11.1 Camera and craft frame

On E, blend the current FP view to the tuning’s forward / down aim. Freeze a **craft frame** when the blend ends:

- Origin in front of the chest, between the work
- `+Z` world up
- `+X` flattened view / player forward at lock time

Mouse is minigame input until the session ends. Optional tiny sway only.

#### 11.2 Authority

`UCraftingComponent` owns the session, camera, type logic, engage button, progress / fail meters, and any presentation actor.

`UHeldItemsComponent` keeps Physics Controls and grip IK (`AnimRef` Hand relative to WeaponBone × item world). Crafting pushes motion into HeldItems.

HeldItems craft API:

- `BeginCraftMotion(Hand, LinearStrength, AngularStrength)`
- `SetCraftAxisLocks(Hand, LockX, LockY, LockZ)`
- `EndCraftMotion(Hand)`
- Later: `PlayCraftIntermission(Hand, Montage, ItemCurve)`

Swing orientation and collision damage stay off for the whole session. `SetExtended` is ignored while a session is live (Player BP gates extend on `IsSessionActive()`, component forces Neutral on start).

#### 11.3 Movement modules

Identity is the class. Look up with `FindMove<T>()`.

| Class | Used by | Motion |
|---|---|---|
| `UGrindActiveCraftMovement` | Sharpened Stone | Physics travel in a slab. Always in contact. |
| `UGrindPassiveCraftMovement` | Hone / grindstone | Physics. Click to engage. |
| `UGrabPullCraftMovement` | Strip, later Form / knife-spear | Mouse angle cone + pull distance. |
| `UCircleAlternateCraftMovement` | Cordage | Animation / opposite-direction slices. |
| `UCircleContinuousCraftMovement` | Tie hatchet | Animation / continuous wrap. |
| `UStrikeCraftMovement` | Knap / forge | Aim then slam. Hold-to-lock is session state. |

A2 authors GrindActive and CircleAlternate only. The component asks `FindMove<UGrindActiveCraftMovement>()`, then `FindMove<UCircleAlternateCraftMovement>()`, and runs the one that hits.

#### 11.4 Presentation and progress appearance

Some types hide bound item render meshes for the session and spawn a presentation owned by `UCraftingComponent`. Bound Item Instances and their `AItemActor`s stay in the hands until a later in-progress replace or a final consume.

Follow target: attach the presentation SKM to the planted `AItemActor` primary mesh (`SnapToTargetIncludingScale` + `PresentationOffset`). Collision and Physics Control stay on the item actors.

Appearance mode (per minigame):

- `LiveMeshes` — real bound meshes. A2 Grind.
- `Morph` — presentation SKM, weights change the silhouette.
- `SkeletalPhase` — presentation SKM, bones / growing length / wrap turns follow phase. A2 Twist.

Morph sample: `Lerp` (continuous from Progress) or `HoldAndPop` (snap on an authored event).

Hide flags: `HideWorkpiece`, `HideTool`. Twist hides both fiber meshes. Grind A2 shows both live stones.

**A2 presentation**

1. Session starts. Bindings are the existing item actors.
2. If appearance is not `LiveMeshes`, spawn `ACraftPresentationActor` and attach it to the planted item.
3. `HideWorkpiece` / `HideTool` → `SetVisibility(false)` on those primary meshes. Collision / simulate stay.
4. Each tick: `SetMorphTarget` / set anim time from session Progress / phase.
5. Session ends: destroy presentation, `SetVisibility(true)` on item actors that still exist.

The player holds `AItemActor` in A2. Presentation is a follow-mesh on the planted item.

#### 11.5 Tuning fields

On `UCraftingMinigameDefinition` (shared look / camera):

- Craft view pitch / yaw offset / blend time
- Appearance mode, morph sample, presentation SKM, hide flags, `PresentationOffset`, morph channel names
- Optional fail-meter rate, events, checkpoints (later)

On the concrete movement:

- GrindActive: stroke `D`, travel volume, min speed (gate) / max speed (cap), planted vs working strengths
- CircleAlternate: slice radians, gesture radius
- GrabPull (later): grab-start angle cone, pull direction, peel `D`
- GrindPassive (later): click engage, hone `R` / `r`
- Strike (later): strike slab; lock-on-hold is session state

Exact numbers wait until the session exists; author placeholders and tune in PIE.

#### 11.6 Engage

Engage is per movement class. GrindActive is always in contact. GrindPassive clicks to engage. GrabPull uses Engage to grab. Strike uses the tool-hand mouse button for lock (LMB if the mallet is left, RMB if right).

#### 11.7 Types

**Grind** — `UGrindActiveCraftMovement`, hands. `DA_Item_Stone` + `DA_Item_Stone` → `DA_Item_SharpenedStone`.

- Left (planted) is the workpiece: stone face up. Interpreter plants this hand.
- Right (working) is the abrader: stone face down. Only this hand is read for progress.
- Always in contact.
- Working hand XY motion inside the volume. Speed below min: no progress. Speed above max: clamped. A stroke is travel `D` then a reverse. Each valid stroke adds progress and a grind cue.
- A2: `LiveMeshes`. Two cobbles the whole session. R / damage returns both stones. Success consumes both, spawns Sharpened Stone into the primary hand.

**Twist** — `UCircleAlternateCraftMovement`, hands. `DA_Item_PlantFiber` + `DA_Item_PlantFiber` → `DA_Item_Cordage`.

- Hide both fiber meshes. Presentation: two strands from the working wrist, finished two-ply growing outward as Progress goes `0 → 1`.
- Both hands planted, strengths near-max. Working arm gets the small authored circle only.
- Gesture: repeated opposite-direction circles. Complete a CW slice of `Slice` radians, then a CCW slice, alternate.
- Left planted on the growing end. Right is the circling hand.
- A2: hands planted. Cues on slice and on length-up.

**Strip** — `UGrabPullCraftMovement`, hands. `DA_Item_FibrousStalk` + Unarmed → `DA_Item_PlantFiber`.

- After the Grind + Twist PoC. Planted hand holds the stalk. Unarmed hand is the working / peel hand.
- Engage = grip a fiber strip. Valid pull of length `D` along the stalk axis adds progress.
- Success: consume stalk, spawn Plant Fiber. Wood Scraps / Kindling: fire system.

**Tie** — `UCircleContinuousCraftMovement`, workbench. Wrap presentation. A3.

**Form** — `UGrabPullCraftMovement`, hands. Clay → green Clay Bowl. Later. Resumable.

**Hammer** — `UStrikeCraftMovement`, station. Flint knapping and forging. Later. Resumable.

**Flesh** — later hide-frame station. Movement class when that craft is authored.

**Hone** — `UGrindPassiveCraftMovement`, grindstone. T3 copper. Live Current/Max writes on the same tool Instance.

#### 11.8 Authored events (later)

A minigame may list events (`FCraftMinigameEvent`: trigger, id, optional arm montage, `bIntermission`). Flip moves the hand and the workpiece together. Flip: later.

#### 11.9 Minigame definition shape

On every `UCraftingMinigameDefinition`:

- One instanced `UCraftMovement` (`Move`). Look up with `FindMove<T>()`
- Appearance: mode, morph sample, presentation SKM, hide flags, `PresentationOffset`, morph channel names
- Craft view / blend
- Events / checkpoints / fail: optional

Gesture numbers and HeldItems restrictions live on the movement class.

- Forge heat / knap map payloads
- AssistOffset two-hand IK (ItemAnimationPipeline)

### 12. Input Mapping Context

Default / gameplay IMC: move, look, Q pickup-place, LMB / RMB activate, R cancel / stack, wheel for containers (and the craft prompt when it is up).

Crafting IMC, pushed for the life of a session:

- Mouse / look → minigame aim / gesture
- Engage (default LMB)
- R → cancel
- Move, Q, swing, and stack-start off
- Wheel unused unless a later minigame flag re-opens recipe select

A2 bindings stay on the Player BP and call:

- `TryStartCraft()` on E while the prompt is visible
- `CycleCraftMatch(int32 Delta)` on wheel while the prompt is visible
- `CancelCraft()` on R while a session is live
- `SetCraftEngage(bool)` on LMB while a session is live
- `NotifyOwnerDamaged()` from the player damage path

Removing the Crafting IMC returns the player to the default mapping.


### 13. Item system contact points

- Create / destroy Instances only through `UItemFactorySubsystem`
- Tags on `UItemDefinition::ItemTags`
- Durability numbers live on `UDurabilityItemFragment` / Instance state (ItemSystemImplementation.txt §10). Crafting applies `DurabilityCost` on success.
- Station place / retrieve: Q-mode, `PlacementOffsetTransform`, shared ReleasePose. Crafting reads the slot.
- Held stacks exist only in hands. `IsHandStacked(EHand)` can stub false until stacks ship.
- Unarmed test: held definition == `UHeldItemsComponent::UnarmedDefinition` (`DA_Item_Unarmed`)
- Snapshot dirty: `UHeldItemsComponent::OnHeldItemsChanged` after attach and after Neutral / Extended actually flips. Station look-at dirties the same way when A3 exists.
