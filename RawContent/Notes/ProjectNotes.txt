ORM Texture note:
In Unreal Engine 5.8, ORM textures must have sRGB disabled and compression set to "Masks" to ensure Occlusion, Roughness, and Metalness channels are treated as linear math data rather than color, preventing visual distortions [1]. For C++ projects, this is achieved by setting SRGB = false and CompressionSettings = TC_Masks on the UTexture2D object to avoid improper gamma correction on packed data [1]. You can read more about texture optimization in Unreal Engine's official documentation. [1, 2, 3] 
[1] [https://github.com](https://github.com/EmbarrassingMoment/RGBPackingTool)
[2] [https://www.youtube.com](https://www.youtube.com/watch?v=9GgZRO4Uxso)
[3] [https://dev.epicgames.com](https://dev.epicgames.com/community/learning/knowledge-base/a3vO/unreal-engine-why-is-my-texture-streaming-pool-giving-me-a-warning)

Architecture reminder:
- Fragments = data + minimal spawn/init hooks. No runtime work in fragments.
- Actors stay thin. Behaviour lives in systems.
- Create / destroy item Instances only through UItemFactorySubsystem.
- StrikeMode is orientation / incidence, not damage type. None = no orient (blunt). Stone is SingleEdged + Blunt primitives. T1 set: ItemSystemImplementation §3.
- Dual-mesh tools: Secondary WeldTo Primary. No Physics Constraint. Material overrides on the Definition for assembled ORM.
- Physical Materials = density / mass + future impact. Named primitives choose candidate damage type.
- Content assets: DA_Type_Name (DA_Item_Stone, DA_Harvestable_Nettle, DA_Recipe_SharpenedStone, DA_Minigame_Grind, DA_Structure_Workbench). Recipes sit next to the primary output item. Minigames live in Content/WoodcraftSurvival/Crafting/Minigames/.
- Crafting: UCraftingComponent lives in Player/ next to HeldItems. Recipe / minigame / movement data stay under Crafting/. Snapshot rebuilds from HeldItems OnHeldItemsChanged (attach + Neutral/Extended). UCraftMovement modules are data. FindMove<T>() selects the interpreter path. Enums in WoodcraftTypes.h.
