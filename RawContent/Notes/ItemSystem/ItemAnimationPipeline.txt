**Item Animation Pipeline – Held Items & FP Arms**
*(Woodcraft Survival – 2026-08-15 – Locked)*

Authoritative description of how item-driven hold poses and temporary montages (pickup, drop, future swings) are handled between `UHeldItemsComponent`, the C++ AnimInstance, and the FPArms AnimBP.


### 1. Goals

- Data-driven hold poses that come from the item itself.
- Gameplay authority stays in `UHeldItemsComponent`; animation presentation stays in the AnimBP.
- Independent left/right arms with no cross-contamination.
- Temporary actions (pickup, drop, later swings) use slots only.
- Works cleanly with the existing Physics Control + Control Rig setup.
- No heavy per-arm state machines for basic holding.
- Safe concurrent / overlapping pickups on both hands.

---

### 2. Data Ownership

| Data                          | Location                          | Type                          | Notes |
|-------------------------------|-----------------------------------|-------------------------------|-------|
| HoldPose                      | `UEquippableItemFragment`         | `TSoftObjectPtr<UAnimSequence>` | Item-specific. Usually a short/static 1–2 frame pose. |
| Default Pickup Montage        | `UHeldItemsComponent`             | `TObjectPtr<UAnimMontage>`    | Single shared asset (right-arm authored). Hard ref. |
| Default Drop Montage          | `UHeldItemsComponent`             | `TObjectPtr<UAnimMontage>`    | Same pattern. Hard ref. |
| ReleasePose (pre-drop snap)   | `UHeldItemsComponent`             | `TSoftObjectPtr<UAnimSequence>` | Shared. Palm-away / letting go. Not per-item. |
| Current runtime HoldPoses     | `UFPArmsAnimInstance`             | `TObjectPtr<UAnimSequence>`   | Hard references after load. |

HoldPose lives on the EquippableItemFragment because it is part of how the item is held.  
The generic 12-frame reach lives on the component as a hard reference because it is fixed and shared by all one-handed items.  
ReleasePose is also component-owned and shared: one palm-away place pose for every item while preview-snapped to a socket.

Unarmed also carries an EquippableItemFragment with its own HoldPose (neutral fists / rest pose).

An individual item may later supply an optional EquipMontage override on its fragment; the component will check for it and fall back to the default if none exists.

### 3. Runtime Classes

**UFPArmsAnimInstance** (C++ parent of the FPArms AnimBP)

```cpp
UCLASS()
class WOODCRAFTSURVIVAL_API UFPArmsAnimInstance : public UAnimInstance
{
	GENERATED_BODY()

public:
	UPROPERTY(BlueprintReadWrite, Category = "Held Items")
	TObjectPtr<UAnimSequence> HoldPose_Left;

	UPROPERTY(BlueprintReadWrite, Category = "Held Items")
	TObjectPtr<UAnimSequence> HoldPose_Right;

	UFUNCTION(BlueprintCallable, Category = "Held Items")
	void SetHoldPose(EHand Hand, UAnimSequence* NewPose);

	UFUNCTION(BlueprintCallable, Category = "Held Items")
	void PlayMontageInSlot(UAnimMontage* Montage, EHand Hand);
};
```

**UHeldItemsComponent** animation responsibilities:
- Owns the shared DefaultPickupMontage and DefaultDropMontage (hard refs).
- Pushes new HoldPoses into the AnimInstance whenever an item actually changes in a hand.
- Starts the pickup/drop montage into the correct arm slot.
- Stores **per-hand** pending pickup data (so left and right can overlap safely).
- Exposes `FinalizePickup(EHand Hand)`.

Access pattern:
```cpp
UFPArmsAnimInstance* ArmsAnim = Cast<UFPArmsAnimInstance>(AnimRefMesh->GetAnimInstance());
```

The component is the single authority for what is in each hand and therefore pushes pose data and montage play commands. The AnimBP does not pull from the component.

### 4. AnimGraph Structure (AnimRef mesh)

Single AnimBP on the **FPArmsMeshAnimRef** (invisible truth source).

Graph order:
```
Neutral/Extended L → LeftArm slot  → Mirror (data table) → left mask ─┐
Neutral/Extended R → RightArm slot → right mask ─────────────────────┴→ Combine
                                                                        ↓
                                                              TwoHanded Slot
                                                                        ↓
                                                              Output Pose → Visible mesh + Control Rig
```

- Base layer always plays the current Neutral/Extended pose per arm.
- LeftArm / RightArm slots are one-arm overrides (pickup, drop, later one-arm montages). Both play the same right-arm-authored montage. The Mirror on the left branch produces the left-side motion. No separate mirrored montage assets.
- **TwoHanded** sits after the L/R combine. Empty slot = combine pose passes through. Guided crafts (Twist, later Tie) play a both-arm montage here. `Montage_SetPosition` scrubs time from minigame phase / slice progress.
- TwoHanded slot Mirror (handedness settings, working hand = Left) is later. A2 plays the authored clip as-is (Left planted, Right working).

The visible mesh (FPArmsMeshVisible) continues to copy the pose from AnimRef and then runs Control Rig for final IK grip adjustment. Grip target locations may still be pulled from `UHeldItemsComponent` on the visible side if convenient.

### 5. Pickup / Equip Flow (One-Handed)

1. **Input** (`TryPickupOrDrop` confirms a valid pickup)
   - Store the target item in the **per-hand** pending slot for that hand (`PendingItem[Hand]`).
   - Begin loading the target item’s `HoldPose` from its EquippableItemFragment.

2. **Play montage**
   - Play the single shared DefaultPickupMontage into the correct arm slot (LeftArm or RightArm) via `PlayMontageInSlot` / `Montage_Play`.
   - The post-slot Mirror node handles left-side correctness.

3. **During the montage**
   - As soon as the HoldPose finishes loading, push it with `SetHoldPose(Hand, LoadedPose)`.
   - The correct pose is therefore already waiting in the base layer when the montage ends.
   - (Pushing on load is simpler than binding MontageEnded just for the pose; the timing difference is only a frame or two.)

4. **AnimNotify** (placed ~frame 9–10 of the 12-frame montage)
   - `UAnimNotify_FinalizePickup` carries an `EHand` property (set when the notify is placed, or inferred from the playing slot).
   - Calls `HeldItemsComponent->FinalizePickup(Hand)`.
   - FinalizePickup for that hand:
     - Destroys the current Unarmed actor (if present).
     - Takes ownership of the existing world `AItemActor`.
     - Creates / configures the Physics Control that drives the item from the AnimRef WeaponBone.
     - Applies left-hand mesh scale flip if needed.
     - Clears that hand’s pending data.

5. **Montage ends**
   - Slot weight returns to 0.
   - Base graph is already playing the new HoldPose → clean settle.

Because pending data is stored per hand, left and right pickups can overlap or fire in quick succession without one overwriting the other.

Notify is placed a couple of frames before the end so the item begins being driven by Physics Control while the hand is still finishing the grasp.

---

### 6. Drop Flow (same pattern)

1. Play the shared DefaultDropMontage into the correct arm slot.
2. AnimNotify near the end performs the actual detach + `EquipUnarmed(Hand)`.
3. Push Unarmed’s HoldPose (as soon as loaded or on the notify) so it is ready when the montage finishes.

Exact blend timings remain open for tuning by the user on the montage assets.

### 6.1 Pre-drop socket snap pose (locked 2026-08-26)

While Q + mouse is held and the item is preview-snapped to a station socket, that arm uses the shared ReleasePose.

- Push one shared **ReleasePose** from `UHeldItemsComponent` (palm facing away from the item, hand opening as if placing it down). Not authored per item.
- Visible-arm Control Rig still reaches toward the item so the hand stays in the neighborhood of the placed mesh.
- **Location only, and loose** — hand stays near the placed mesh. Grip rotation stays off while snapped so the wrist follows the place, not the hold pose.
- The item itself stays at `SocketTransform × PlacementOffsetTransform`. The arm yields to the item, not the other way around.
- When the preview snap is lost (still holding Q + mouse, no socket in range): restore that hand’s Extended HoldPose and the normal full grip (position + rotation).
- On release commit (socket attach or world drop): existing drop montage / EquipUnarmed path.

This pose is presentation only. It does not change pickup, place, or stack rules.

### 6.2 Guided two-hand slot (locked 2026-09-03; stages 2026-09-05)

Live-item crafts (Grind, Tie Split working hand) keep per-arm Neutral or brace poses. Control Rig follows the live items on hands with grip IK on.

Stage arm motion plays the current `FCraftStage::Montage` on AnimRef into slot `TwoHanded`:

- Intro at the front. `UAnimNotify_CraftIntroDone` on this clip only reports montage seconds to `UCraftingComponent` and enables the move.
- After intro, seek `lerp(IntroEndTime, ArmsLength, Progress)` when `bProgressDrivesMontage`. Twist leaves that flag false and writes position from slices.
- Stage `Presentations` spawn at AnimRef / ArmsPivot. During intro they seek to the FPArms playhead. After intro they sample Progress (`lerp(IntroEndTime, OwnLength, Progress)` or morph weights). A presentation with no montage holds its spawn pose.
- Stop the slot on teardown or phase change.
- `PlayMontageInSlot` today is per `EHand`. TwoHanded play / scrub / stop is a third slot name on the AnimRef instance, called from the crafting component.

Hybrid stages (Tie Stage 1 Split, Stage 2 Seat): two-hand clip on AnimRef, Visible Control Rig on the working hand only.

- Visible AnimInstance: `bGripIK_Left` / `bGripIK_Right` plus the existing grip transforms. One Control Rig, two gated branches.
- Working item transform comes from the craft interpreter, not from AnimRef `WeaponBone`.
- Off-hand grip IK off so the brace / hold matches AnimRef 1:1.
- Stage change is a hard swap of those bools after `EndCraftMotion`.

`bTwoHanded` items (logs, bows) stay a separate path: primary Neutral/Extended plus AssistOffset offhand IK. They do not use this slot.

### 7. Open Points

- Exact frame for the FinalizePickup notify (currently ~9–10 of 12). Needs feel testing.
- Drop montage length and feel relative to pickup.
- Optional item-specific EquipMontage override.
- TwoHanded slot Mirror when working hand is Left (handedness settings).
- AssistOffset two-hand IK for `bTwoHanded` items.
- Per-hand grip IK bools on the Visible AnimInstance / Control Rig (needed for Tie Stage 1).
- Future polish: temporarily override the Control Rig IK target to the world item being reached for during the pickup montage (so the hand homes toward the real object instead of the current held/Unarmed grip). Requires a short-lived “reach target override” that is cleared on FinalizePickup or MontageEnded. Not required for the first working version.
