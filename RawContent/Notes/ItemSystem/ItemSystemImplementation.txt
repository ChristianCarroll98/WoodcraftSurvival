**Full Description of the Intended Item System**  
*(Updated 2026-08-26 – Procedural swing orientation + incidence live; SetExtended live; Stab impulse still TODO; part durability / break results remain designed-not-implemented)*

### 1. High-Level Goals
- Fully data-driven item definitions using Primary Data Assets + Fragments.
- `UItemInstance` is the long-lived identity of a specific item. It is only destroyed when the item is truly consumed, broken, or used up in crafting.
- `AItemActor` is the current world representation and **may** be destroyed and recreated (storage, inventory, load/save, etc.).
- For normal world pickup/drop the Actor is **not** destroyed — it is attached/detached.
- Clean separation of concerns:
  - **Data** → Definitions + Fragments
  - **Runtime state** → `UItemInstance` (long-lived)
  - **World presence** → `AItemActor` (disposable)
  - **Creation** → `UItemFactorySubsystem`
  - **Player holding logic** → `UHeldItemsComponent`
  - **Presentation** → Animation, Control Rig, Physics Control (mostly Blueprint + component)

### 2. Core Code Types

**UItemDefinition** (Primary Data Asset)  
Contains an array of `UItemFragment*` instances.  
This is the pure data definition of an item type (Stick, Axe, Unarmed, etc.).

**UItemFragment** (abstract base)  
Lightweight, instanced, edit-inline objects that add specific capabilities.  
Examples: Equippable, Durability, Fuel, Damage, etc.

- Fragments are **primarily pure data**.
- Data is exposed as `UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)`.
- Two lightweight virtuals (no mutable runtime state, no per-frame work):

```cpp
/** Called only once when a new UItemInstance is first created from a Definition.
 *  Use for default runtime values (CurrentHealth = MaxDurability, etc.). */
virtual void OnItemInstanceCreated(UItemInstance* Instance) {}

/** Called every time an AItemActor is spawned/initialized for an Instance.
 *  Use only for actor-side setup (collision responses, components, mesh tweaks).
 *  Never write default values into the Instance here. */
virtual void OnItemSpawned(AItemActor* ItemActor) {}
```

**UItemInstance**  
Runtime object that holds a pointer to its `UItemDefinition` Primary Data Asset and any per-instance mutable state (CurrentHealth, UniqueId, etc.).  
Created with `NewObject<UItemInstance>(GetTransientPackage())`.
Never stacked. Only destroyed when the item is consumed/broken.

**AItemActor**  
The actual actor in the world.  
- Owns a Primary Static Mesh Component (+ optional Secondary).  
- Holds a reference to its `UItemInstance`.  
- `InitializeFromInstance()` sets the mesh(es) and calls `OnItemSpawned` on every fragment.  
- May be destroyed and later recreated from the same Instance (storage, etc.).  
- For normal ground ↔ hand cycles the actor is kept alive.

**UItemFactorySubsystem** (`UWorldSubsystem`)  
Single authority for creation. Access via `GetWorld()->GetSubsystem<UItemFactorySubsystem>()` or a cached `TObjectPtr` on components.

Public API:
```cpp
UItemInstance* CreateItemInstanceFromDefinition(UItemDefinition* Definition);
AItemActor*    SpawnItemActorFromDefinition(UItemDefinition* Definition, const FTransform& SpawnTransform);
AItemActor*    SpawnItemActorFromInstance(UItemInstance* Instance, const FTransform& SpawnTransform);
```

- `CreateItemInstanceFromDefinition` creates the Instance and calls `Fragment->OnItemInstanceCreated` on all fragments.
- `SpawnItemActorFromInstance` spawns the Actor and calls `Actor->InitializeFromInstance` (which runs `OnItemSpawned`).
- `SpawnItemActorFromDefinition` is the convenience path (Create + Spawn).

**EHand** (in `WoodcraftTypes.h`)
```cpp
UENUM(BlueprintType)
enum class EHand : uint8
{
	Left,
	Right,
	None
};
```

### 3. Equippable System & Collision (Finalized 2026-08-15)

**UEquippableItemFragment**  
Holds `bTwoHanded`, `StrikeMode` (`EItemStrikeMode`), and Neutral/Extended pose soft refs.  
In `OnItemSpawned` it applies `TRACE_EQUIPPABLE = Block` on Primary and Secondary (if present).

**Naming convention (locked 2026-08-19)**  
Concrete Item fragments use the form `<Capability>ItemFragment` (e.g. `UEquippableItemFragment`, `UDurabilityItemFragment`).  
The abstract base remains `UItemFragment`.  
This keeps Item and Harvestable fragment families clearly distinct.

**Collision Approach (hybrid – locked)**  
- Base collision settings come from the **“Item” Collision Profile** (Project Settings → Collision → Presets):
  - Object Type = `Item`
  - Collision Enabled = QueryAndPhysics (or as desired)
  - Common responses (WorldStatic, WorldDynamic, Pawn, etc.)
- EquippableItemFragment then overrides only the specialized channel **after** the profile is applied:

```cpp
// Correct order – profile first, then specialized response
PrimaryMeshComponent->SetCollisionProfileName(TEXT("Item"));
PrimaryMeshComponent->SetCollisionResponseToChannel(TRACE_EQUIPPABLE, ECR_Block);

// Identical for SecondaryMeshComponent if present
```

- `TRACE_EQUIPPABLE` **must** be `ECR_Block` (not Overlap).  
  `SweepSingleByChannel` only generates hits against Block responses.
- This keeps the bulk of collision data in one editable profile while letting the EquippableItemFragment own its single responsibility.
- Both Primary and Secondary meshes receive the same treatment.

**Hand Ownership**  
- One primary hand owns the item.  
- `bTwoHanded == true` → opposite hand becomes secondary.  
- Player can hold two different one-handed items at the same time.

### 4. Animation & Attachment Architecture (Locked)

Two skeletal meshes on the player:

- **FPArmsMeshAnimRef** (invisible, no collision, truth source)  
  Pure animation authority. Plays montages and hold poses. Zero IK.  
  Physics Control is driven from `WeaponBone_L` / `WeaponBone_R`.

- **FPArmsMeshVisible** (visible)  
  Copies pose from AnimRef, then Control Rig IK to grip targets supplied by `UHeldItemsComponent`.

**Physics Control**  
- One `UPhysicsControlComponent` on the character.  
- Drives the held item relative to the corresponding AnimRef WeaponBone.  
- Gives real momentum while still following the hand.

**Dynamic Grip Transform** (every frame)
```
Relative = AnimRef.HandBone.GetRelativeTransform(AnimRef.WeaponBone)
GripTarget = Relative * ItemWorldTransform
```
Left-hand IK works without extra transform mirroring.

**Left-hand item mesh mirroring (implemented)**  
- Only the mesh component is scaled: `SetRelativeScale3D(FVector(-1.f, 1.f, 1.f))` when held in left hand.  
- Scale is forced back to `(1,1,1)` on detach.  
- Actor root scale stays positive (avoids Physics Control issues).

### 5. Held Item Safety (implemented)

`PreventItemStuck(EHand)` runs every tick from `UHeldItemsComponent`.

- Measures distance between AnimRef **HandBone** and the current **GripLocation**.
- Hysteresis (enter ~55, exit ~40 — tune as needed).
- When stuck: changes collision **responses** on WorldStatic, WorldDynamic, and custom channels (macros) COLLISION_ITEM and later COLLISION_STRUCTURE/COLLISION_CREATURE to `Ignore`.  
- When free: restores them to `Block`.  
- **Never** uses `SetCollisionEnabled(NoCollision)` — that invalidates Physics Control bodies.
- Light Control Rig stretch on the visible arms so the hand stays visually glued.

### 6. UHeldItemsComponent Responsibilities

- Manages both hands (always a valid item — Unarmed when empty).
- Creates / destroys Physics Controls on attach / detach.
- Dynamic grip transform calculation every frame.
- Left-hand mesh mirroring.
- `PreventItemStuck` safety.
- Owns the targeted-item query (`FindLookedAtItem`) and will drive highlight logic.
- Provides clean Blueprint API.
- Owns per-hand stack state (single UItemInstance or TArray of same-Definition Instances? TBD).
- Owns one UInstancedStaticMeshComponent per hand (created once, enabled only while that hand holds a stack. Owns? Components created on player. Maybe created from BeginPlay in HeldItemsComponent to get the references easily, or can create from engine and assign to EditDefaultsOnly class variable. TBD).
- Exposes TryStartStack(EHand TargetHand) for intentional stack creation (called from player input, tentatively [R] + mouse click).

**Pickup / Drop API (implemented 2026-08-15)**

```cpp
// Low-level
bool TryPickup(AItemActor* Item, EHand Hand);
bool TryDrop(EHand Hand);

// Q-mode entry point
bool TryPickupOrDrop(EHand Hand);

// Helper
bool GetIsUnarmed(EHand Hand) const;
```

**TryPickupOrDrop decision tree (updated 2026-08-20)**
- Looking at valid item + hand is Unarmed → Pickup
- Looking at valid item + hand occupied → Do nothing (or drop, or swap, TBD)
- Looking at empty space + hand occupied → Drop (entire stack if count > 1)
- Looking at empty space + hand Unarmed → Do nothing

**Implementation notes**
- Target is locked at the moment of input confirmation.
- `FindLookedAtItem` uses a small sphere sweep (default ≈8 cm radius, 250 cm distance) on `TRACE_EQUIPPABLE` from the camera.
- Ignores owner + both currently held items.
- Prefer letting Physics Control + IK “suck” the item into pose. No forced teleport for normal world items.
- Hard teleport / snap reserved mainly for re-equipping Unarmed.
- 12-frame reach montage + AnimNotify finalization still pending (current path finalizes immediately for testing).

**Unarmed handling inside pickup/drop**
- `GetIsUnarmed(EHand)` compares the held item’s Definition against the stored `UnarmedDefinition`.
- On pickup of a real item: previous Unarmed actor is simply `Destroy()`ed.
- On drop: `EquipUnarmed(Hand)` is called immediately after detach.

### Held Stacks (Locked 2026-08-20)

Hand-held stacks are a lightweight, same-type-only special case managed entirely by UHeldItemsComponent (may change when final plan created at start of implementation). They intentionally reuse the player-facing feel of containers without being full container actors.

**Starting a stack**
- Both hands must currently hold the same stackable Definition.
- Player input calls `TryStartStack(EHand TargetHand)` on UHeldItemsComponent (R + LMB/RMB).
- The function evaluates the condition and, if valid, moves one item from the opposite hand into the target hand, creating a stack of 2.
- This leaves the ability to hold and use two separate matching items (e.g. two sticks) completely intact.
- UI tooltip for the control is future work.

**While a hand holds a stack (count ≥ 2)**
- Primary actions (swing, throw, examine, etc.) are disabled on that hand.
- Extending the stack hand enables container-style take/put with the free hand (one item at a time, same type only).
- Q + mouse button on the stack hand drops the entire stack.

**Collapsing a stack**
- Taking the last item out of a stack of 2 simply leaves two normal single items.
- The player can immediately re-stack them with the same R + mouse chord if desired.

**Data & Visuals**
- UItemInstance remains never stacked (each Instance stays unique and long-lived).
- The extra AItemActor is destroyed when stacking begins; only its UItemInstance is kept.
- One UInstancedStaticMeshComponent exists per hand on UHeldItemsComponent. It is enabled only while that hand has a stack, using the item’s mesh and a small set of pre-authored relative transforms (max count comes from UStackableItemFragment).
- When count returns to 1 the ISMC is disabled and the normal single-item mesh is restored.

**Relationship to real containers**
- Real containers continue to use AItemActor + UItemContainerComponent.
- Shared take/put + UI logic will later be extracted into a common interface or thin handler so stacks and real containers feel identical when extended.

### 7. Player Structure

- C++ `AWoodcraftCharacter` owns the `UHeldItemsComponent`.
- WoodcraftPlayer Blueprint subclasses it.
- C++ owns state and rules; Blueprint owns presentation (animation, Control Rig, Physics Control tuning).
- `UHeldItemsComponent` caches `TObjectPtr<UItemFactorySubsystem> ItemFactory` set in `BeginPlay`.

**Input (current interim approach)**
- Enhanced Input actions are currently wired in the Player Blueprint.
- Q + LMB / Q + RMB combos fire `TryPickupOrDrop`.
- A separate `PickUpMode` bool Input Action toggles outline/highlight visibility.
- Plan: move binding + Q-mode / PickUpMode state into C++ on `AWoodcraftCharacter` once the core feel is solid.

### 8. Unarmed Handling (Locked)

- Unarmed is a real item (`DA_Unarmed`).
- Store **only** the `UItemDefinition*` (no permanent Unarmed Instances).
- On equip: `Factory->SpawnItemActorFromDefinition(UnarmedDefinition)` then normal attach path.
- On replace with a real item: simply `Destroy()` the Unarmed actor.
- Both hands start with Unarmed.
- Dropping an item immediately re-equips Unarmed in that hand.
- Eliminates null-hand special cases.

### 9. Item Activation & Stab (Design Locked 2026-08-20)

Activation (LMB/RMB without Q-mode) for supported items switches the hand between Neutral and Extended poses. The poses themselves are already authored as soft object references on `UEquippableItemFragment` (`NeutralPose` / `ExtendedPose`). Unarmed uses the same path.

**Call site (partially live)**
- Player BP currently calls `SetExtended(EHand Hand, bool bExtended)` on `UHeldItemsComponent` alongside the AnimBP extend bool.
- `SetExtended` only stores `FHandState.bExtended`. That flag gates collision damage and procedural orientation.
- Still TODO when transitioning *to* Extended:
  1. Optionally push Neutral ↔ Extended from C++ instead of BP (poses already live on the fragment).
  2. Look up a `UStabItemFragment` on the held item’s Definition.
  3. If the fragment exists, apply a linear impulse to the item’s PrimaryMesh.

**UStabItemFragment** (pure data, follows `<Capability>ItemFragment` naming)
- `float ImpulseStrength` — primary tunable value. Applied as a world-space linear impulse (direction starts as camera / look forward; can later gain a bias toward item-local forward).
- Optional `float AngularImpulseStrength` (default 0) for rotational snap if desired later.
- No damage numbers, multipliers, or special-case logic. The fragment only answers “how hard do I shove the physics body on extend.”

**Why this works with Physics Control**
Current control strengths are intentionally soft (Linear ~3, Angular ~5). A short impulse temporarily dominates, the item surges forward, the hands follow via the existing grip / Control Rig, and the Physics Control then recovers the item toward the new Extended target pose. This produces the desired “punchy” feel without fighting the laggy free-swing combat style.

**Damage remains 100% collision-driven**
All damage (Unarmed punch, spear tip, thrown rock, arrow, dropped item, etc.) uses the single shared path:
- Collision occurs on a held, extended item
- Named primitive (`Blunt`, `Point`, `Sharp`, `Head`, …) → candidate type
- World mesh speed ≥ `GMinItemSpeed` and impulse ≥ `GMinImpulse`
- Incidence can demote Slash/Pierce → Blunt (`EItemStrikeMode` + cones in `WoodcraftTypes.h`)
- Amount from impulse; Physical Material later for impact sound / VFX

### 9.1 Collision Damage, Incidence & Procedural Orientation (Live 2026-08-26)

**Incidence (AItemActor::OnItemMeshHit)**
- Candidate type from named simple-collision primitive (closest Box/Sphere/Sphyl to ImpactPoint).
- Strike axes always from Primary (handle), not the Secondary head — constraint flex under impact would otherwise skew the test.
- Incoming dir = `FHandState.LastItemVelocity` → live velocity → `-NormalImpulse`.
- Slash: face rejection vs Primary X + along-edge half-cone around +Y (Single) or ±Y (Double).
- Pierce: cone around Primary +Z. `StrikeMode == None` never keeps Slash/Pierce.

**Procedural orientation (UHeldItemsComponent::UpdateProceduralOrientation)**
- Edged tools only (`SingleEdged` / `DoubleEdged`). Pierce / None skip.
- Gate: hand extended AND owner-relative primary speed ≥ `GMinItemSpeed`.
- Intent: `SetLookDelta` (Player BP each tick) → camera right/up → projected onto WeaponBone Z plane.
- Writes only `SetControlTargetOrientation` on the existing Physics Control. Parent WeaponBone still carries position. Skeletal-anim contribution is disabled while active and restored on the falling edge.
- Strength (angular + linear) scales with look speed × `FHandState.MassScale`. Constants live only in `WoodcraftTypes.h`.
- Wrist: asymmetric CW/CCW limits around projected WeaponBone +Y. Right vs left sign mapping so both hands feel the same. 1D twist is rate-limited and never leaves the legal band.
- Preferred edge (`OrientEdgeSign`) flips with `GWristHysteresisDeg`. SingleEdged stays on +Y until forced; DoubleEdged stays on the current sign while it remains legal.
- Arm follow is Control Rig only (pole lerp toward grip). Hold pose does not twist with the item; wrist pinch on extreme side swings is accepted.

No activation flag or special-case damage path is required. Higher velocity from the impulse naturally increases impact severity.

**Applies equally to**
- Unarmed (fists) — just put a `UStabItemFragment` on `DA_Unarmed` with appropriate strength.
- Spears, knives, sharpened sticks, etc.

Future polish (not required for first version): direction bias enum, impulse application point (COM vs tip socket), temporary Physics Control strength modulation during the activation window, stamina cost.

### 10. Part Durability & Tool Break (Design Locked 2026-08-25)

Tools with a Secondary mesh (handle + head) track durability independently for each part. Simple items continue to use the single `CurrentHealth` path.

**Runtime state on `UItemInstance`**
- `CurrentHealth` — Primary / handle durability (existing field).
- `CurrentHeadHealth` / `MaxHeadHealth` — Secondary / head durability.  
  `CurrentHeadHealth = -1` means the item has no secondary part (or the head has already been removed).

**Seeding at craft / assembly time**  
When a composite tool is created the crafting system identifies the two source Instances by role (Primary/handle and Secondary/head) and copies their remaining durability values into the new Instance. Max values are taken from the sources (or a fraction of them). Non-composite items ignore the head fields.

**Break definition lives on `UDurabilityItemFragment`**  
Any item that has durability can break. The fragment now also carries the replacement data and a sharpen flag:

```cpp
UENUM()
enum class EBreakPartBehavior : uint8
{
	KeepHolding,      // new item stays in the same hand
	DetachAndSpawn,   // new item(s) appear in world with velocity
	Destroy           // nothing left of this part
};

USTRUCT()
struct FToolPartBreakResult
{
	GENERATED_BODY()

	UPROPERTY(EditDefaultsOnly)
	TSoftObjectPtr<UItemDefinition> ItemDefinition;

	UPROPERTY(EditDefaultsOnly)
	EBreakPartBehavior Behavior = EBreakPartBehavior::DetachAndSpawn;

	UPROPERTY(EditDefaultsOnly, meta = (ClampMin = "1"))
	int32 Count = 1;

	/** If true, the new Instance receives the remaining durability of the broken part.
	 *  Only set true on the main remaining/broken piece (e.g. Broken Handle or Broken Head).
	 *  Extra scraps / kindling leave this false and receive full durability from their own Definition. */
	UPROPERTY(EditDefaultsOnly)
	bool bTransferDurability = false;
};

// On UDurabilityItemFragment
/** When true the 25 % Max-Head scrap threshold applies (sharpenable tools).
 *  When false the part simply breaks as soon as its Current reaches 0 (ignore Max). */
UPROPERTY(EditDefaultsOnly, Category = "Durability")
bool bCanBeSharpened = false;

UPROPERTY(EditDefaultsOnly, Category = "Break")
TArray<FToolPartBreakResult> PrimaryBreakResults;   // handle / Primary breaks

UPROPERTY(EditDefaultsOnly, Category = "Break")
TArray<FToolPartBreakResult> SecondaryBreakResults; // head / Secondary breaks
```

**Break execution**  
When a part’s Current durability reaches ≤ 0 (and, for the head, the Max has also fallen to the scrap threshold — see below):

1. Cache hand, remaining durability of the surviving part, Secondary mesh world transform + linear/angular velocity, and any other needed state.
2. Clear the hand and destroy the old composite Instance (and its Actor if still present).
3. Iterate the relevant break-result array:
   - Create a new Instance from each `ItemDefinition` via the normal factory path.
   - If `bTransferDurability` is true, overwrite `CurrentHealth` (or head values) with the cached remaining value.
   - If Behavior == KeepHolding, equip the new Actor into the same hand.
   - If Behavior == DetachAndSpawn, spawn the Actor in the world at the cached transform with the cached velocity so it flies off naturally.
4. The old tool is fully gone; only the new ordinary Instances remain.

Example (copper hatchet):
- SecondaryBreakResults → one entry: CopperScrap, DetachAndSpawn, Count=1, bTransferDurability=false.
- PrimaryBreakResults → BrokenHandle (KeepHolding, bTransferDurability=true) + 2–3 kindling (DetachAndSpawn, bTransferDurability=false).

Broken Handle and scrap items are ordinary Definitions that use the normal single-durability path, FuelItemFragment, etc.

**Sharpening interaction points**  
Sharpening is implemented as crafting recipes (see CraftingSystem). A recipe restores some `CurrentHeadHealth` and permanently lowers `MaxHeadHealth` by an amount authored on that recipe (crude stone = higher loss, grindstone = lower loss).  

Visual and mechanical dulling are driven by the `CurrentHeadHealth / MaxHeadHealth` ratio (shape key or material parameter, damage multiplier, incidence bias toward Blunt).  

**Scrap threshold (global starting constant)**  
Only checked when `bCanBeSharpened == true` on the Durability fragment.  
A head is treated as final scrap when `CurrentHeadHealth ≤ 0` **and** `MaxHeadHealth ≤ 0.25 × OriginalMaxHeadHealth` (the Max that was seeded at craft time). 25 % is the initial hard cutoff; it can later be moved to a CVar or per-fragment value if needed.

When `bCanBeSharpened == false` the Max check is ignored and the part simply breaks as soon as its Current reaches 0.

Until the relevant break condition is met the head stays attached and simply becomes progressively worse (when sharpenable).
